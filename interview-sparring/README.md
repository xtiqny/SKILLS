# Interview Sparring · JD 驱动的诊断式面试陪练

> 不是模拟面试，是面试私教。根据 JD 精准出题，动态追踪弱项，最终输出知识缺口地图。

## 为什么做这个

模拟面试工具很多，但都有同一个问题：**随机出题，答完就完，不追踪你到底哪里弱。**

Interview Sparring 的区别：

| | 传统模拟面试 | Interview Sparring |
|---|---|---|
| 出题依据 | 题库随机 | **JD 硬性要求 + 你简历的缺口** |
| 答错之后 | 给标准答案，下一题 | **换角度追问，确认你真实水平** |
| 结束后 | "表现还不错" | **知识缺口地图 + 补漏路径 + 简历调整建议** |
| 下次再练 | 从头开始 | **自动加载上次弱项，对比进步** |

一句话：**Mock Interview 是模考，Sparring 是私教。**

## 快速开始

### 安装

```bash
# 复制到 Claude Code skills 目录
cp -r interview-sparring ~/.claude/skills/

# 或者在 ai-skills 仓库中直接使用
```

### 使用

```bash
# 方式 1：直接说
"帮我练一下 AI 应用工程师面试"

# 方式 2：指定 JD 文件
/interview-sparring ~/jds/某公司_AI应用工程师.txt

# 方式 3：给 URL
/interview-sparring https://example.com/job/12345

# 方式 4：针对上次弱项复练
"sparring 继续上次的"
```

## 工作流程

```
Phase 0 · 加载历史
  ↓ 读取上次弱项（如果有）
Phase 1 · 准备
  ↓ 读简历 + 读 JD → 提取硬性要求 → Gap 分析 → 考察计划
Phase 2 · 陪练循环（5-10 题）
  ↓ 出题 → 你答 → 评分 → 追踪弱项 → 动态调下一题
Phase 3 · 诊断报告
  ↓ 知识缺口地图 + 最危险缺口 + 补漏路径 + 简历建议
Phase 4 · 持久化
  ↓ 保存报告 + 写入 Memory + 追加历史
```

### Phase 2 陪练循环示例

**出题**：
```
[第 3/8 题 · 考察域: Agent 架构 · 难度: ⭐⭐⭐]

Q: JD 要求"有 Agent 开发经验"。如果让你设计一个客服 Agent，
   它需要查知识库、调工单系统、必要时转人工——你会选什么架构模式？为什么？
```

**你回答后**：
```
📊 评估

得分: 5/10
✅ 对的: 提到了 ReAct 模式和工具调用
❌ 漏的: 没有考虑失败处理——工具调用失败怎么办？转人工的触发条件是什么？
💡 提示: 想想 Agent 的"退出策略"

→ 继续下一题 / → 你想补充刚才的回答吗？
```

## 状态管理

Interview Sparring 有 4 层状态机制，保证跨题、跨会话都不丢数据：

| 层 | 机制 | 作用 |
|---|---|---|
| 会话内 | Claude Code TaskCreate/TaskUpdate | 10 题循环中每题结果可靠追踪 |
| 会话后 | Write → `~/.sparring/sessions/` | 完整诊断报告持久化 |
| 跨项目 | Claude Memory 摘要 | 任何对话自动看到上次弱项 |
| 长期趋势 | `~/.sparring/history.jsonl` | 多次陪练的进步曲线 |

### 复练时自动加载

第二次运行时：
```

```

## 设计原则

1. **JD 驱动** — 每道题锚定 JD 某条要求，不随机出题
2. **诊断式** — 目标是找缺口，不是排名打分
3. **动态调整** — 前面答错的领域后面会追问
4. **不给标准答案** — 模拟真实面试压力
5. **有记忆** — 跨会话追踪弱项和进步

---

## 适用场景

- 面试前 1-2 周的集中准备
- 学完新内容后验证掌握程度
- 换方向时快速评估知识储备
- 长期持续练习，追踪进步曲线

## 不适用

- 想要完整面试模拟（全流程含自我介绍、反问环节）→ 用 `mock-interview`
- 想要标准答案背诵 → 直接问 ChatGPT
- 非技术面试（HR / 行为面）→ 本 skill 专注技术考察
