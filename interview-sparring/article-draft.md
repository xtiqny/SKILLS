# 我做了一个 AI 面试陪练工具，它和"模拟面试"完全不同

> 用 Claude Code Skill 实现 JD 驱动的诊断式面试陪练，每次练完给你一张"知识缺口地图"。

---

## 起因：模拟面试练了 10 次，面试还是挂

我最近在面 AI 工程师的岗位。

准备的方式和大多数人一样：找个 AI 模拟面试，出 10 道题，答一遍，看看哪个答得不好。

问题是——**练了很多次，每次都感觉"还行"，但真面试还是挂在意想不到的地方。**

后来我想明白了：模拟面试的问题不是"不够真实"，而是**不够精准**。

- 它不知道我要面的岗位**真正考什么**
- 它不会因为我某个问题答错就**追着不放**
- 它不会告诉我**到底哪块知识最危险**
- 练完 10 次的结果和练完 1 次的结果**没有区别**——因为它不记得上次的表现

我需要的不是一个模拟面试官，而是一个**面试私教**。

---

## 区分一下：Mock Interview vs Sparring

Sparring 这个词来自拳击——不是正式比赛，是有教练指导的对练。教练会根据你的弱点调整打法，目的不是赢你，是帮你找到破绽。

| | 模拟面试 (Mock) | 面试陪练 (Sparring) |
|---|---|---|
| 出题 | 题库里随机抽 | 从 JD 硬性要求 + 你简历缺口精准命中 |
| 答错后 | 给标准答案，下一题 | 换个角度再问一次，确认你是真不会还是表述问题 |
| 结束后 | "整体表现 7/10" | 一张知识缺口地图，告诉你面试最可能挂在哪 |
| 下次再练 | 从零开始 | 自动加载上次弱项，对比进步 |

一句话：**Mock 是模考，Sparring 是私教。**

## 它怎么工作

### 第一步：给它一份 JD

你可以直接说"帮我练 AI 应用工程师面试"，也可以指定一份 JD 文件。

它会自动做三件事（你看不到）：

1. **解析 JD**——区分硬性要求、核心能力、加分项、HR 水分
2. **对比你的简历**——找出简历没覆盖的硬性要求（最危险的缺口）
3. **制定考察计划**——优先考你最可能挂的地方

你看到的只是一句话：

```
📋 陪练计划
岗位: AI 应用工程师
考察域: 5 个，按风险排列
预计: 8 道题，约 25 分钟
准备好了吗？开始第一题。
```

### 第二步：一题一题来

```
[第 1/8 题 · 考察域: Agent 架构 · 难度: ⭐⭐⭐]

Q: JD 要求"有 Agent 开发经验"。如果让你设计一个客服 Agent，
   需要查知识库、调工单系统、必要时转人工——你会选什么架构？
```

注意几个设计决策：

- **每次只出一题**——不是一口气 10 题让你看完崩溃
- **不给标准答案**——模拟真实面试压力，你得自己想
- **评分后给 hint 不给答案**——"你漏了失败处理，想想 Agent 的退出策略"

你答完后：

```
📊 评估
得分: 5/10
✅ 对的: 提到了 ReAct 和工具调用
❌ 漏的: 没考虑失败处理——工具调不通怎么办？转人工的判断逻辑？
💡 提示: 想想 Agent 不只要"能做事"，还要"知道做不了时怎么退"
```

如果你这题答得不好，下一题**不会跳到别的领域**——它会换个角度再问一次 Agent 相关的，确认你到底是不会还是刚才没想到。

如果你答得很好，它会追问一层——验证你不是背的，是真理解。

### 第三步：诊断报告

8 题答完，出一份报告：

```
知识缺口地图:
| 考察域       | JD 优先级 | 得分 | 判定       |
|-------------|----------|------|-----------|
| RAG 检索优化 | 🔴 硬性   | 8/10 | ✅ 扎实    |
| Agent 架构   | 🔴 硬性   | 4/10 | ❌ 危险缺口 |
| MCP 协议     | 🟡 核心   | 5/10 | 🟡 需加强  |
| 搜索/ES      | 🟡 核心   | 7/10 | ✅ 可以    |

🚨 最危险缺口:
Agent 架构（4/10）— 这是 JD 硬性要求，面试官一定会问。
补漏建议: 精读 ReAct 论文 + 用 LangGraph 实现一个最小 Agent（约 4 小时）

📝 简历调整:
- "RAG 系统开发" → 加粗前置
- "了解 MCP" → 删掉，面试官会深挖你答不上来的
```

**这张"知识缺口地图"是整个工具最值钱的输出。** 它不是告诉你"表现还行"，而是精确到每个考察域的分数和判定，配上"面试最可能挂在这"的风险评估。

### 第四步：下次再练，自动对比

一周后你补完了 Agent 的知识，再跑一次：

```
📂 发现历史记录
上次: AI 应用工程师（2026-04-06）
❌ Agent 架构 4/10 · 🟡 MCP 5/10

这次要针对性加强这两个弱项吗？
```

练完后对比：Agent 架构从 4/10 → 7/10。**进步可见。**

## 技术实现（给开发者看）

这是一个 Claude Code Skill，核心就是一份 SKILL.md（结构化 prompt）+ 2 个参考文件。

### 状态管理是关键

面试陪练最难的不是出题，是**记住前面的表现并据此调整**。一个 Skill 本质上只是一段 prompt，它没有数据库、没有 state machine。

我用了 4 层机制解决：

```
会话内:  TaskCreate/TaskUpdate  → 每题结果写入 Claude Code 原生任务系统
会话后:  Write → ~/.sparring/   → 完整报告持久化到本地文件
跨项目:  Claude Memory           → 一行摘要写入 memory，任何对话自动加载
长期:   history.jsonl            → 所有历次陪练的索引，追踪进步曲线
```

会话内的 TaskCreate 是最关键的——它让 LLM 不需要靠"回忆上下文"来记住前 5 题的结果，而是有一个可靠的外部记录。出下一题之前先 TaskGet 回顾所有任务状态，比 LLM 自己总结靠谱得多。

### 文件结构

```
interview-sparring/
├── SKILL.md              ← 5 个 Phase 的完整逻辑（~250 行）
├── README.md
└── references/
    ├── domain-map.md     ← 8 大 AI 知识域 + JD 关键词映射
    └── scoring-rubric.md ← 评分标准（0-10 每档含义 + 追问策略）
```

总共不到 500 行。没有后端、没有数据库、没有 API。**一个 markdown 文件就是整个产品。**

## 谁适合用

- **正在面试 AI 相关岗位的人** — 有 JD，想精准备
- **学完一块新知识想验证的人** — 不确定自己是"看懂了"还是"真会了"
- **准备换方向的人** — 快速评估自己在新领域的知识储备
- **Claude Code 用户** — 直接安装使用

## 谁不适合

- 想要完整面试模拟（含自我介绍、反问环节）→ 用 mock-interview
- 想背标准答案 → 直接问 ChatGPT
- 不用 Claude Code → 目前只支持 Claude Code Skill 形式

## FAQ

**Q: 和直接让 ChatGPT 模拟面试有什么区别？**

ChatGPT 模拟面试是随机出题 + 单次评分，不会根据你的 JD 精准命中硬性要求，不会追踪弱项动态调整，不会跨会话记住你的进步。Sparring 解决的就是这三个问题。

**Q: 不用 Claude Code 能用吗？**

目前不能。但 SKILL.md 的逻辑是通用的——你可以把它改成一个 System Prompt 在任何 LLM 上跑，只是会失去 TaskCreate 状态追踪和 Memory 跨会话记忆。

**Q: 题目会不会太简单 / 太难？**

每个考察域从中等难度开始。答对追问更深一层，答错降级换角度。难度是动态的。

**Q: 能覆盖非技术面试吗？**

目前只做技术考察（RAG / Agent / MCP / Prompt / 系统设计等）。HR 面和行为面的陪练不在范围内。

**Q: 多次练同一个 JD 有用吗？**

有用。第二次会自动加载上次弱项，针对性出题。你能看到分数变化——这就是"进步曲线"的价值。
